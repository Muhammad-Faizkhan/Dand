# Session 2026-11-01: backend integration, step 1 (auth)

First step of wiring the app to the DanD API
(`https://dandbackend-production.up.railway.app`, source in
`../Dan_D_Backend/backend`, endpoints in its `API-REFERENCE.md`).

Backup of the whole project before any change:
`../_backups/dandcollection-2026-11-01-pre-integration.tgz` (no `build/`, no `.dart_tool/`).

## What changed

New files:

- `lib/core/api/api_client.dart`: JSON client with a bearer token, one shared
  refresh on 401, and `ApiException` carrying the server's `error` message.
  `upload()` posts multipart to `/api/uploads`. The base URL comes from
  `--dart-define=API_URL=...` and defaults to Railway.
- `lib/core/api/token_store.dart`: `SecureTokenStore` (flutter_secure_storage)
  for the app, `MemoryTokenStore` for tests.
- `lib/core/api/auth_api.dart`: register, login, logout, email verification,
  forgot/reset password, `me`.
- `lib/widgets/api_feedback.dart`: `showAppMessage` (existing snackbar style)
  and `submitAuth`, which runs an auth call and either navigates or shows the error.
- `test/api_client_test.dart`: refresh, failed refresh, error message, token save.

Changed:

- `AuthController` takes an optional `AuthApi`. **With no API it behaves exactly
  as before** (every call succeeds locally, no validation), which keeps the
  existing tests and design reviews offline. `login()` and `logout()` now return futures.
- `ProfileController` takes an optional `ApiClient`. `uploadAvatar()` uploads,
  then `PATCH /api/users/me {avatarUrl}`.
- Login, Create Account, Verify Email, Enter Code / Enter OTP, Forgot Password
  and Create New Password call the API. Create New Password is now stateful with
  real controllers. Layout is unchanged.
- `main.dart` builds the client, starts on `/main` if a refresh token is saved,
  and sends the user to login when a refresh fails (`navigatorKey`).
- `test/widget_test.dart` passes an offline client to `DanDCollectionApp`.
- `pubspec.yaml`: `http`, `flutter_secure_storage`.

The API needs a username but the design has no field for it, so it is derived
from the email plus a 4-digit suffix (`AuthController._usernameFrom`).

When the server sets `EXPOSE_DEV_CODES=true`, the code screens show the code
in a snackbar ("Test build: your code is …").

## Verified, and how

is 3.35.1 and cannot resolve this project, so it is left alone for the other apps.

- `flutter analyze`: no issues.
- Non-golden tests: 66 pass, 1 fails, `responsive_test` "phone landscape":
  `/add-item` overflows by 246 px. **The untouched backup fails the same way**,
  so this predates this session.

  font rasteriser drift between platforms. The modified app's per-golden

  so no screen's rendering changed (the auth screens included).
  Do **not** run `--update-goldens` on Windows: it would overwrite the macOS baselines.

  below), and creating a test account writes rows, which needs confirmation.
