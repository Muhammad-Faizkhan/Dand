# Session log — 3 September 2026

Six rounds of fixes against the Figma design, in the order they were raised.
Every measurement below was taken off the design exports numerically, not by
eye. At the end of the session: `flutter analyze` clean, **112 tests passing**,
debug APK building.

---

## 1. Bottom navigation alignment

**Reported:** the red indicator did not line up with the icons.

**Cause.** The four screenshots supplied were 1x Figma exports (390 pt frame on
black padding), so they could be measured directly. The design's tab centres
are **60.5 / 131.5 / 258.5 / 329.5** — deliberately *not* evenly spaced, so the
pairs hug the sides and leave the middle to the docked "+". The code positioned
the **indicator** at those centres but laid the **icons** out with four equal
`Expanded` slots, i.e. 48.75 / 146.25 / 243.75 / 341.25. That ~13 pt mismatch
was the whole bug.

**Fix.** `widgets/app_bottom_nav.dart` rebuilt so tab content and indicator
both derive their x from one set of centre fractions — they cannot drift apart
at any width. The rest of the bar was corrected to the measured design at the
same time:

| Property | Was | Now (design) |
|---|---|---|
| Bar | 93 tall, `#070709` | 91 tall, `#09090B`, 1px `#161617` hairline |
| Indicator | 53 x 10 `#E4232B`, straddling the top edge | 55 x 6 `#A2141A`, flush with the top edge, bottom corners r4 |
| Glyphs | 36 square, uniform | 23.8 tall (20.8 for the map pin), common baseline 45.6 above the bar bottom |
| Labels | Inter 12, `#9A9AA3` | Inter 400/14, `#5F5F60` inactive, `#E4232B` active |
| "+" | flat `#E4232B` | top-right `#9F1319` → bottom-left `#DC2128` gradient |
| Bottom gap | fixed | 19.8, widened to the device's gesture inset |

The indicator animates between tabs (220 ms `easeOutCubic`), and
`AppBottomNav.heightOf(context)` replaced `barHeight` for scroll padding so
content clears the gesture area.

Verified by `test/bottom_nav_golden_test.dart`: four goldens for diffing
against the frames, plus 16 assertions that the indicator centre equals the
active icon centre across 360x640, 390x844, 393x873 and 430x932.

## 2. Blurry / pixelated UI

**Cause.** The entire Figma export is **1x** — a third of what a 3x phone
needs. Worst case was the nav glyphs: 62 px sources drawn at 36 pt.

**Fix.** Every asset resampled to 2x (Lanczos + a light unsharp pass); the
opaque photographs moved to quality-94 4:4:4 JPEG. Result: **double the
resolution for 5.5 MB, down from 5.9 MB at 1x**. The `nav_*` glyphs stay PNG
and carry a flat `AppColors.navBar` background rather than transparency —
that is how they leave the export, and it keeps their darkest pixels reading
as they do in Figma. Icons now draw at their design 23.8 pt from 124 px
sources.

> **Still outstanding.** These are interpolated pixels, not new detail. For
> genuinely retina-crisp artwork the frames need re-exporting from Figma at
> 3x. Nothing in the code changes if they land on the same filenames.

## 4. Onboarding CTA off the bottom of the screen

**Cause.** The splash and onboarding CTAs were positioned by a design Y
measured from the top of the 844 frame (`top: 741.h`), but onboarding renders
inside a `SafeArea` — so that offset was applied *below* the status-bar inset.
On an iPhone 16 that stacked 59 pt onto the 741, putting the button at
807–857.5 on an 852 pt screen: 5.5 pt off the bottom and entirely inside the
home-indicator zone.

**Fix.** Both CTAs anchored to the **bottom** of the frame, where the design
puts them (53 above the bottom for onboarding, 51 for splash), floored at
`viewPadding.bottom + gap` so a taller gesture area or an Android 3-button bar
pushes them up instead of under.

| Screen | Before | After | Safe bottom |
|---|---|---|---|
| 390x844 design | 788–838 | **741–791** | 810 |
| 393x852 | 807–857.5 ✗ | **748–798.5** | 818 |
| 440x956 | — | **839–896** | 922 |
| 412x892 (3-button) | — | **783–836** | 844 |
| 360x640 | — | **562–600** | 640 |

The design-frame case now lands on 741–791 — exactly the Figma position, which
the old code missed by 47 pt. `test/safe_area_test.dart` pins both CTAs against
the status bar and the bottom inset at all five profiles.

## 5. Authentication flow

**OTP (the main one).** The field was:

```dart
TextField(controller: TextEditingController(text: auth.otp), onChanged: auth.setOtp)
```

A throwaway controller built **inside `build`**. Every keystroke rebuilt the
screen, which built a fresh controller with the selection dropped to offset −1
— so backspace and mid-code editing were unpredictable. Replaced with
`OtpInput`: the six design boxes are now pure decoration over one long-lived,
zero-size `TextField` whose controller lives in the widget's state. The caret
is pinned after the last digit, so deleting always removes the digit the user
can see is last, wherever they tapped. Digits-only, capped at six, paste and
`AutofillHints.oneTimeCode` work, auto-submits on the sixth digit.
`/enter-code` and `/enter-otp` are the same screen, so Create Account and
Forgot Password are fixed by construction and cannot drift.

**Resend timer.** Was the hardcoded string `'0:30'`. Now a real
`Timer.periodic`: counts down, "Resend code" is grey and inert while it runs,
turns red at zero, and tapping it clears the entered digits, confirms with a
snackbar and restarts the countdown.

**Password eyes.** `AppTextField.showToggle` now defaults to **true**, so any
field marked `obscure` gets an eye without the screen asking — Login, Create
Account (x2), Reset Password (x2) and Change Password (x3), eight fields. The
old grey `show` / `hide` text became `visibility_outlined` /
`visibility_off_outlined` with a widened tap target. The card form's CVC opts
out; there is no room in that three-up row.

**Profile photo.** The create-account avatar opens a new `ImageSourceSheet` —
take a photo / choose from gallery / remove — styled like the app's other
sheets. The platform permission keys were already declared.

`test/auth_flow_test.dart` covers all of it, including two tests that pin the
old failure modes specifically: the code surviving a parent rebuild with the
caret intact, and a stray mid-string caret being pulled back to the end.

## 6. Home header icons — *blocked on an export*

The message and bell icons in the header are 3D renders in Figma, the same
style as the `nav_*` glyphs. The app draws flat Material icons instead. The
supplied crop is ~1x, where each icon is about **20 px wide** — nothing usable
can be upscaled out of it, and the two files were never in the export.

Plumbing is in place so the artwork drops straight in. `AssetIcon`
(`widgets/asset_icon.dart`) checks the bundle once per path, cached
process-wide, and draws the export when present or the Material glyph when
not — no exception, no console noise. `AppAssets` declares the final paths and
the header renders through them.

> **To finish this:** export both icons from Figma at 3x (they draw at
> 17.6 pt, so a 3x export of a 24 pt source is comfortable), save as
> `assets/images/icon_messages.png` and `assets/images/icon_notifications.png`,
> and hot **restart** — not reload, the bundle lookup is cached. No code
> change. `test/asset_icon_test.dart` covers both the fallback and the swap.
